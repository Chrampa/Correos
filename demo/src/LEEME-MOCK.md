# Contrato de integración del mock

El build debe leer `demo/datos/mock-fixtures.json` (catálogo de seis personas acordado en DEMO.md; los fixtures antiguos de 15 personas no cumplen ese guion). Inyectar **antes del mock** un script síncrono `window.__DEMO_DATA__ = JSON.parse(...)` o una constante JSON equivalente, escapando `<`, U+2028 y U+2029. No hay peticiones para leer fixtures ni dependencias externas.

Orden: CSP al principio del head; estilos originales y `demo-banner.css`; fixtures inline; `mock-api.js` inline; script original; adaptador UI del build; `demo-banner.js` inline. Todos los recursos deben estar embebidos. El mock rechaza incluso fetch de recursos relativos, deliberadamente: el objetivo de DEMO.md es cero red posterior al documento inicial. Para `file:` acepta las rutas /api locales.

`window.DemoMock.ready === true` verifica arranque. API pública: `setScenario('normal'|'lista-vacia'|'error-carga'|'conexion-fallida'|'vista-fallida'|'zip-vacio')`, `fixtures` (copia), `routes`, `getState()` (copia), `documentURL(id)`, `rewriteLinks(root)`, `blobURL(blob)`, `createPdf()`, `createXlsx(payload)`, `createZip([[nombre,bytesOTexto],...])`, `dispose()` y `await networkCheck()` (true y error de consola esperado).

**Adaptador UI que debe instalar el build después del original:** envolver `pintarRecibidos` para llamar síncronamente `DemoMock.rewriteLinks(document)` tras cada render, antes de permitir interacción. MutationObserver es solo respaldo. Los links reescritos conservan `data-demo-id`; PDF real generado en memoria, sin SVG disfrazado. El mock conserva URLs de documentos mientras sean utilizables; `dispose` las revoca al reiniciar. Las URLs creadas por descargar() original también quedan registradas para permitir sus enlaces.

El build/adaptador conserva los IDs originales y debe aplicar las restricciones de edición/importación/recursos de DEMO.md, sustituir mensajes heredados de Outlook/envío real, precargar prueba@example.invalid y mostrar los controles de escenarios. `demo:notice` lleva el texto en `event.detail`, para mostrarlo como nota/toast. `demo:downloads` abre el panel implementado por demo-banner.js; `demo:closed` restaura aviso y texto tras reemplazar body. Renombrar bCarpeta a «Ver descargas demo». La llamada global `comprobarRebotes()` se invoca a 1200 ms del fin; si no existe, el mock aplica el rebote y emite `demo:job`. Sondeo no hace avanzar el reloj.

Excel/ZIP cargados se sustituyen siempre por muestras: no se inspecciona el binario del usuario. `/api/excel` usa un escritor OOXML/ZIP STORE propio local sin dependencias; conserva columnas y `extra` con todas las celdas como inlineStr (nunca fórmulas). El panel genera Excel inicial, PDFs auténticos y ZIP local con registro. El log incluye `demoKey` adicional interno para identificar intentos sin depender de posición. Pendiente y Saltado los pinta la UI, no se duplican en log.

Prueba: `node demo/tests/mock-api.test.js`. Usa VM y reloj falso únicamente en el test; no modifica tiempos de producción. La prueba de navegador/CSP y la geometría a 360 px corresponden a QA del artefacto final del build, no se sustituyen por este test unitario.

## Correcciones 3b: rutas, navegación y temporizadores

Las rutas se normalizan contra el directorio del documento: se aceptan `/api/info`, `api/info` y `/subcarpeta/api/info` cuando esa subcarpeta aloja el documento. En Windows `file:///C:/api/info` y la variante dentro del directorio de la demo se normalizan explícitamente; se rechazan otra unidad, host UNC, protocolo u origen. No se admite una ruta API bajo cualquier carpeta ajena.

Navigation API: el listener `navigate` cancela destinos distintos del documento actual (salvo fragmentos y Blob registrado) mediante `preventDefault()` cuando el evento es cancelable. Esto cubre asignación directa de `location`, `assign` y `replace` en Chrome probado sobre HTTP. No intentamos sobrescribir `Location`, que no es reemplazable. `beforeunload` solicita confirmación como red de seguridad; requiere activación previa y el usuario puede permitir salir. `pagehide` limpia temporizadores, pero NO impide peticiones. En navegadores sin Navigation API, eventos no cancelables y contextos donde no se despacha `navigate` (por ejemplo restricciones de orígenes opacos), NO existe una garantía general contra navegación directa desde JS: solo se mantienen el bloqueo de enlaces, formularios, open y transportes del artefacto auditado. Tampoco se bloquea la barra de direcciones ni acciones privilegiadas del navegador. No se afirma que `connect-src` bloquee navegación.

No se requiere añadir una directiva CSP experimental: `navigate-to` carece de soporte interoperable y no sería una barrera fiable. El build debe conservar exactamente `connect-src 'none'; form-action 'none'; base-uri 'none'` dentro de su política actual y regenerar automáticamente los hashes de scripts modificados. Una garantía de navegación universal en motores sin Navigation API requiere políticas externas del navegador/contenedor; no puede prometerse con HTML estático. La publicación debe declarar Chrome probado y esos límites.

Antes de devolver `/api/estado`, el mock actualiza la variable léxica global original `tRebote` al ID del lote. Así la condición de `sondear` no crea el callback heredado de 150 s sin handle. Es una integración explícita con la UI auditada: si cambia ese nombre o condición, hay que revisar el adaptador. Permanece solo el timer propio de 1200 ms, cancelado al parar/salir/iniciar otro lote y protegido por identidad del job. No se intercepta ni acelera el reloj global.

`node demo/tests/mock-api.test.js --browser` usa Chrome instalado y CDP sin paquetes. Reemplaza los dos scripts y sus hashes CSP **en memoria** sobre el artefacto existente, sin escribir dist ni ejecutar un build concurrente. Sirve esa copia sobre HTTP para verificar assign/href/replace y cero peticiones al destino; luego entrega la misma copia mediante intercepción CDP de un documento `file:///C:/...` y carga realmente el input Excel para verificar seis personas pintadas. Es evidencia del código corregido y de la resolución file, pero no sustituye regenerar y probar el dist definitivo. También comprueba el nombre accesible del diálogo, devolución de foco y anuncio final polite. Los correos editables/de prueba se limitan ahora a `@example.invalid`; `no-valido@dominio-no-permitido.invalid` es el caso negativo explícito.
